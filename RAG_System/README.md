## Актуальность

В корпоративной среде объемы документов огромны. RAG-система — это алгоритм, который быстро находит релевантную информацию, экономя время руководителей, инженеров и менеджеров.  
Забыли название файла или где искать ответ? Система вспомнит и предоставит точный результат.
Ежедневно мы сталкиваемся с вызовами: огромные архивы документов, забытые названия файлов, потерянные детали в отчетах.  
Необходимость быстрого поиска ответов без глубокого погружения в каждый файл.  
RAG-система решает эти проблемы, используя AI для мгновенного извлечения данных и генерации ответа, повышая эффективность команд.  

- База данных с документами слишком большая?  
- Забыли название документа или исследования?  
- Необходимо точно и быстро достать нужную информацию?  

RAG-Система поможет вам решить ваши бюрократические проблемы.  

## Компоненты RAG-системы

1. Хранение данных  
Чанки (кусочки) документов хранятся в векторной БД в текстовом и математическом виде (PostgreSQL + pgvector)  
2. Поиск  
Запрос переводится на язык математики и с помощью косинусного сходства из БД достаются схожие документы  
3. Генерация  
LLM генерирует ответ на основе вашего запроса и поданного из БД контекста.  

## Выбор эмбеддинговой модели

Эксперименты включали русские модели (ruBert) и мультиязычные (multilingual-e5, Qwen-Embeddings).  
Оценивались модели по точности поиска на корпоративном датасете с русским текстом.

## Реализованные фичи

- Гибридный поиск + ранжирование: Поиск по эмбеддингам + BM25 + RRF Ranker  
- Контекст в чате: Множественные вопросы по одному документу. Модель помнит весь контекст (Функция по рефразированию запросов)  
- Источники: Предоставление файлов-источников, которые сразу можно скачать и проверить  
- Многопользовательская работа: Авторизация пользователей, сохранение истории чатов, возможность задавать вопросы параллельно с нескольких устройств  
- Разный формат данных: При создании базы данных алгоритм сохраняет структуру таблиц, формулы и генерирует описания к изображениям  
- Умный чанкинг: Чанкинг по разделителям, если превышается лимит токенов, то по предложениям + при нарезке таблицы дублируются заголовки и номер таблицы  
- Удобный интерфейс: Интуитивный дизайн + подробная инструкция для быстрого старта  
- Логирование запросов: Сохранение запросов в БД для анализа использования агента и частых ошибок  

Настройка ноутбука по созданию БД позволяет обрабатывать отсканированные PDF (OCR), промпт и модель для генерации подписей к изображениям  

Регистрация пользователей намеренно сделанна отдельным скриптом, а не динамически на сайте для безопасности использования системы внутри компании

## Точки роста проекта

1. Масштабирование (через сервер)  
2. Возможность присылать в качестве ответа изображения из документов  
3. Создание нескольких баз данных под нужды пользователей и возможность переключаться между базами в чате
4. Возможность прикрепить и задать вопросы по своему документу

## Воспроизведение проекта

Весь проект реализован внутри docker container.  
Для использования системы скачайте необходимые библиотеки, а также ollama, запустите ее и скачайте нужную LLM.  

1. Запустите скрипт notebooks/uploading_data.py (Обращайте внимание на комментарии)
2. Зарегистрируйте пользователя с помощью notebooks/new_user_registration.py (```chainlit run new_user_registration.py --host 0.0.0.0 --port 8002```)
3. Запустите app_main.py (```chainlit run app_main.py --host 0.0.0.0 --port 8000```) (Порты желательно должны отличаться)

Пользуйтесь!
